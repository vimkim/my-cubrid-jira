## Description

### SQL 과 shell 의 구분

일반적인 값 round-trip, 결정적인 단일 세션 DML 과 DDL, 안정적인 오류 결과는 공개 SQL 테스트로 검증한다. 여러 세션의 순서를 제어하거나 서버 재시작·강제 종료·복구, 유틸리티와 환경 변경을 수행해야 하는 동작은 비공개 shell 테스트로 검증한다. C++ 내부 API 로만 검증할 수 있는 불변 조건을 SQL 또는 shell 로 검증한 것처럼 기록하지 않는다.

테스트 디렉터리, 파일 이름, helper, answer 비교와 정리 방식은 각 저장소의 기존 사례를 따른다. 테스트가 반환한 process exit status 만으로 성공을 판단하지 않고 runner 의 실행 사례 수, 비교 결과와 assertion 결과를 확인한다.

현재 SQL grammar/answer 비교에서는 `SHOW HEAP OOS` 의 안정적인 열만 추출하거나 volatile ID 를 제거하는 기존의 이식 가능한 방법을 확인하지 못했다. 대응 shell 사례가 같은 fixture/configuration 의 물리 상태를 확인하더라도 실제 공개 SQL 실행 자체를 관찰한 것으로 기록하지 않는다. SQL 논리 결과와 shell 물리 증거의 적용 범위 및 차이를 구분한다.

### 로컬 검증

기존 로컬 CI 설정을 기본 실행 경로로 사용한다. 초기 build mode 는 optdebug 이며 SQL 은 회사 설정과 호환되는 JDBC 기본 실행을 검토한다. shell 의 page size 와 SA/CS 실행 방식은 검증하려는 동작에 맞게 사례별로 기록한다. 별도의 전체 release 또는 page-size 조합 실행은 조사 결과에서 필요한 이유가 확인될 때 제안한다.

SQL 테스트 모음과 shell 테스트 모음의 실행 시간은 각각 준비와 정리를 포함해 기록한다. 매 사례를 실행할 때마다 엔진, testcase 와 runner 의 revision, 실제 실행 목록, 결과 위치와 cleanup 상태를 함께 남긴다. 현재 작업은 계획과 증거 조사이므로 새 testcase 를 실행하거나 회사 GHA 를 시작하지 않는다.
