## CBRD-27193

[Complete report](../../issues/CBRD-27193-page-buffer-program_f6cac31_codex.md)

**이슈 수행 목적**: 페이지 버퍼의 사용·보호 회계와 오류 후 진행을 일관되게 유지하고, 페이지 상태와 처리 비용을 관측하여 필요한 기능 및 성능 개선을 검증할 수 있게 한다.

**이슈 수행 이유**: 현재 소스에 fix·보호·로딩 기록의 소유권 불일치, flush 실패 정리 누락과 실행되지 않는 예비 공급 경로가 남아 있다. 과거 직접 API 검증과 개발자 댓글에도 회계 오류 및 debug 서버 중단이 보고되었다. 설정·진단·성능 비교의 공백을 함께 다루되, 독립적으로 판단할 수 있는 문제는 각 하위 과제로 처리해야 한다.

**영향**: 해당 조건을 사용하는 엔진 작업의 페이지 접근 보호, 오류 복구와 진행에 영향을 줄 수 있으며, 개발자·QA·운영자의 상태 진단과 변경 효과 판단도 어렵게 한다. 과거 실행 보고와 현재 소스에서 도출한 위험을 구분한다. 현재 기준 빌드의 운영 장애, 데이터 손상, 발생 빈도와 전체 영향 릴리스는 확인하지 않았다.

**이슈 수행 방안**: TBD - ANALYSIS 단계에서 해결 방안과 구현 범위를 결정한다. 하위 과제별로 필요한 결과와 검증·종료 판단을 관리하며, 이미 기록된 기능 결정은 해당 근거와 함께 유지한다.

## CBRD-27194

[Complete report](../../issues/CBRD-27194-initialization-finalization_f6cac31_codex.md)

**이슈 수행 목적**: 페이지 버퍼의 정상 초기화, 중간 실패, 종료와 재초기화에서 실제로 확보하고 초기화한 자원만 정리하며, private LRU가 없는 설정을 크기 0 할당의 반환값에 의존하지 않고 처리한다.

**이슈 수행 이유**: 기준 소스에 대상과 다른 타입을 사용한 `direct_victims` 초기화 크기, AOUT 보조 함수와 공통 종료 함수의 중복 mutex 파괴, private LRU 개수가 0일 때의 무조건 할당과 NULL 실패 판정이 남아 있다. 호출자까지 보면 공통 종료 함수가 다시 호출되는 실패 경로도 있어, 세 지점의 수정과 함께 초기화 단계별 정리 책임을 확인해야 한다.

**영향**: 초기화 실패를 진단하는 개발자와 해당 설정·할당 동작을 사용하는 실행 환경에 영향을 줄 수 있다. 잘못된 자원 정리는 최초 실패에 정리 오류를 더할 수 있고, private LRU가 0개일 때 NULL을 돌려주는 할당 동작에서는 불필요하게 초기화를 실패시킨다. 현재 기준 빌드에서 크래시나 서비스 장애를 재현한 결과는 없으며, 발생 빈도와 지원 플랫폼별 영향은 미확인이다.

## CBRD-27196

[Complete report](../../issues/CBRD-27196-sx-latch-survey_f6cac31_codex.md)

**이슈 수행 목적**: CUBRID의 B-tree split/merge에서 SX(shared-exclusive) page latch가 재시작과 읽기 차단을 줄이는지 조사하고, 도입·보류·미도입 중 하나를 근거와 함께 권고한다.

**이슈 수행 이유**: 현재 B-tree는 READ에서 WRITE로 승격하지 못하면 삽입을 WRITE 하강으로 재시작하거나 merge를 생략·재시작한다. 2026-08-07 작성자 코멘트는 실제 CUBRID split/merge의 이점 검토를 요청했다. 기존 타 DBMS 비교와 flush 복사 제거 가능성만으로 이 요청에 답할 수 없으므로 실제 호출 경로와 비용을 구분해 판단해야 한다.

**영향**: WRITE 하강으로 재시작하는 경우 추가 탐색과 WRITE latch 점유가 발생하고, merge를 생략하는 경로도 있다. 발생 빈도와 처리량·지연·공간 사용에 미치는 크기는 미확인이다. SX를 추가하면 수정 후보의 조기 직렬화와 상태·대기열 관리 비용도 생기므로 성능 개선을 전제하지 않는다.

## CBRD-27211

[Complete report](../../issues/CBRD-27211-direct-victim-wait-policy_f6cac31_codex.md)

**이슈 수행 목적**: 페이지 버퍼의 direct victim 대기자 선택 규칙이 high/low priority 작업의 대기와 CPU 비용에 미치는 영향을 확인하고, 현행 주기 `4`의 유지 또는 변경 판단에 필요한 근거를 남긴다.

**이슈 수행 이유**: 현재 선택 함수는 모든 호출자가 공유하는 카운터를 증가시키고 네 번째 호출마다 low priority 큐를 먼저 시도한다. 그 밖의 호출에서는 high priority 큐를 먼저 시도하며, 실패하면 low priority 큐도 확인한다. 이 주기의 적정성과 공유 atomic 연산의 비용을 분리한 측정 근거가 확인되지 않아 조사할 필요가 있다.

**영향**: 재사용할 버퍼 슬롯이 부족해 direct victim을 기다리는 일반 작업과 vacuum 등 내부 작업이 대상이다. 선택 순서가 부하와 맞지 않으면 어느 한쪽의 대기가 늘어날 수 있으나, 현재 자료만으로 성능 저하의 발생 여부·빈도·크기를 확정하지 않는다. `4`는 실제 배정 비율이나 최대 대기시간을 보장하는 값이 아니다.

**이슈 수행 방안**: TBD - ANALYSIS 단계에서 해결 방안과 구현 범위를 결정한다.

**이슈 수행 목적**: 기존 page buffer(default)와 대안 구현(v2)을 병행 유지하면서 각각을 선택해 실행·비교하고 default로 복귀할 수 있는 도입 전략을 정리한다. 비교 가능한 범위, 검증 단계, 유지보수 책임과 도입 판단 근거를 확보한다.

**영향**: 개발자와 QA가 대안 구현의 효과를 기존 구현과 구분해 평가하고 회귀 시 복귀하는 작업에 영향을 준다. 선택 계층과 공통 코드의 변경은 default에도 회귀를 만들 수 있고, 결함 수정 누락이나 서로 다른 계측 의미는 비교 결론을 왜곡할 수 있다. 현재 성능 이득, 추가 QA 비용, 운영 적용 범위는 확인되지 않았다.

## CBRD-27262

[Complete report](../../issues/CBRD-27262-flush-error-recovery_f6cac31_codex.md)

**이슈 수행 목적**: 페이지 flush 준비가 실패해도 BCB의 dirty/flushing 상태와 아직 반영되지 않은 변경의 추적 정보를 일관되게 유지하고, 후속 flush와 대기자가 진행할 수 있게 한다.

**이슈 수행 이유**: 기준 소스에서 `pgbuf_bcb_mark_is_flushing` 이후 TDE 암호화 또는 DWB 준비 함수가 오류를 반환하면, 정규 write 실패 경로의 상태 복구를 거치지 않고 반환한다. 오류 분기의 실제 도달 조건과 단계별 정리 책임을 확인할 필요가 있다.

**영향**: 해당 오류 반환이 발생하면 flush를 수행할 주체가 사라졌는데도 BCB가 flushing 상태로 남을 수 있다. 이 상태는 교체 후보 제외와 후속 동기 flush의 완료 대기 위험으로 이어진다. 과거 이슈 본문은 오류 주입 후 checkpoint와 서버 종료 대기를 보고하지만, 현재 기준 빌드의 실행 결과와 운영 발생 빈도, 고객 장애 및 데이터 유실은 확인하지 않았다.

## CBRD-27263

[Complete report](../../issues/CBRD-27263-deallocation-protection-accounting_f6cac31_codex.md)

**이슈 수행 목적**: `OLD_PAGE_PREVENT_DEALLOC` 요청이 자신이 등록한 해제 방지 보호만 해제하고, 성공·실패·재정렬 경로에서 불필요한 감소나 등록 잔존을 만들지 않도록 한다.

**이슈 수행 이유**: 기준 소스에서 lock-free READ fix는 보호 등록을 건너뛰고 공통 해제를 실행한다. 일반 fix 실패와 ordered fix 재정렬 사이에도 실제 등록 여부를 전달하지 않는 경로와 요청 페이지의 잔여 보호를 정리하지 않는 출구가 있다. 카운터 원자 연산만으로는 이 소유권 불일치를 막을 수 없다.

**영향**: heap 체인 순회가 의존하는 vacuum 회수 방지 판단이 부정확해질 수 있다. 보호가 부족하면 페이지를 다시 얻는 작업의 오류나 debug assert로, 보호가 남으면 해당 BCB가 유지되는 동안 빈 페이지 회수 지연으로 이어질 가능성이 있다. 과거 계측 보고와 현재 소스의 제어 흐름은 확인했으나, 현재 기준 빌드의 최종 질의 실패·서버 중단·데이터 손상 및 고객 노출은 확인하지 않았다.

**이슈 수행 방안**: TBD - ANALYSIS 단계에서 해결 방안과 구현 범위를 결정한다.

## CBRD-27264

[Complete report](../../issues/CBRD-27264-direct-victim-emergency-path_f6cac31_codex.md)

**이슈 수행 목적**: 일반 공급 경로의 활동이 줄어도 재사용 가능한 페이지 버퍼가 있는 조건에서 direct victim 대기자가 잊히지 않고 진행하도록, 실행되지 않는 예비 배정 경로를 처리한다.

**영향**: 새 페이지를 올릴 버퍼를 기다리는 서버 스레드는 이 예비 경로의 도움을 받을 수 없다. 다른 공급이 계속 없으면 할당 대기가 길어지고 timeout 처리에 이를 가능성이 있다. 현재 엔진에서 해당 상황을 재현하지 않았으며, 실제 지연·고객 장애·영향 릴리스는 확인하지 않았다.

## CBRD-27266

[Complete report](../../issues/CBRD-27266-statistics-semantics_f6cac31_codex.md)

**이슈 수행 목적**: page buffer의 논리 flush, 파일에 기록한 페이지 양, 읽기 요청, victim 후보를 구분하여 관측할 수 있도록 지표의 집계 단위·완료 시점·수집 조건을 명확히 한다.

**이슈 수행 이유**: 현재 소스에서 SHOW의 counter 컬럼 9개는 폐기되어 NULL을 반환하지만, 대체 관측 경로인 statdump의 쓰기·읽기 지표도 동일한 사건을 세지 않는다. DWB 경로의 별도 집계와 논리 flush 지표의 활성화 조건을 구분하지 않으면 부하 비교의 기준을 잘못 정할 수 있다. SHOW에 남아 있는 `Victim_candidate_pages`도 내부 victim 후보와 다른 집합을 센다.

**영향**: DBA와 성능 분석자가 DWB 설정 변경, checkpoint, victim flush의 동작을 비교할 때 처리한 논리 페이지 수와 파일 쓰기량을 혼동하거나 미수집 값을 작업량 0으로 해석할 수 있다. 집계 지점과 조건은 소스로 확인했으며, 운영 오판 사례·빈도·성능 손실 규모는 확인하지 않았다.

## CBRD-27267

**이슈 수행 목적**: big private victim queue가 제한된 victim 탐색에 후보를 공급하는 조건과 효과를 확인하고, 현행 정책 유지 또는 변경의 근거를 마련한다.
