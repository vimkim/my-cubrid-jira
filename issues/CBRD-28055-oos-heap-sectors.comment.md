## OOS 브랜치에서도 같은 원인으로 팬인과 병렬도가 낮아진다

OOS 브랜치(`feature/oos-merge`)의 shell `cbrd_27236_merge` 실패를 분석하다가, 이 이슈와 같은 원인이 OOS 파일에서도 나타나는 것을 확인했다. 오버플로 파일 섹터를 더하는 수정을 정할 때 OOS 파일도 함께 검토해 주기를 요청한다. OOS가 develop에 병합되면(PR #7990) 같은 코드가 develop에 들어간다.

OOS는 행이 4,060바이트(16K 페이지의 inline target)를 넘으면 큰 가변 컬럼부터 OOS 파일로 옮기고 heap에는 24바이트 참조만 남긴다. 정렬할 키의 개수와 크기는 그대로인데 heap 섹터만 줄어든다. `btsort_get_num_data_sectors` 는 `hfids[i].vfid` 의 heap 섹터만 세므로 팬인 상한이 낮아진다. `btsort_check_parallelism` 도 `hfids[0]` heap의 페이지와 섹터로 병렬도를 정하고, 섹터 수가 병렬도보다 적으면 1을 돌려준다.

아래는 debug 빌드에서 조건마다 1회 실행한 값이라 방향만 보여준다. release 빌드와 큰 테이블에서는 재지 않았다. 만들어진 인덱스 내용은 develop과 같았다.

### 측정 1: 인덱스 컬럼이 OOS로 옮겨지는 테이블

`tv (id int not null, v varchar(4100) collate utf8_bin)` 에 약 4,100바이트 값 27,000행을 넣고 `create index i_v on tv (v)` 를 실행했다. `index_build_buffer_size=512K`, 병렬은 `index_build_parallelism=8`, `parallel_index_build_page_threshold=16` 이다.

| | develop `785021e` | OOS `30292700ac` |
|---|---|---|
| heap | 9,001 페이지, 평균 레코드 4,129바이트 | 105 페이지(2섹터), 평균 레코드 49바이트 |
| 직렬 빌드 | 런 222개, 팬인 16 후 14, 병합 2회, 14.1초 | 런 222개, 팬인 2, 병합 8회, 21.2초 |
| 병렬 설정 | 워커 8개, 워커 팬인 16, 5.6초 | 워커 1개(직렬), 병합 8회, 12.2초 |

OOS에서는 heap 2섹터를 기준으로 팬인이 최소값 2까지 떨어진다. heap 섹터가 2개뿐이라 병렬 분할도 직렬로 바뀐다.

### 측정 2: 인덱스 컬럼은 heap에 남고 다른 컬럼이 옮겨지는 테이블

shell `cbrd_27236_merge` 의 `tw` 테이블(키 1,799자, 정렬하지 않는 pad 2,304자, 행 4,151바이트)이다. OOS에서는 pad가 OOS 파일로 옮겨진다.

| | develop | OOS |
|---|---|---|
| heap 데이터 섹터 | 141 | 61 (OOS 파일 71섹터는 따로) |
| 워커 8개의 팬인 | 16 | 7 |
| 정렬 입력 | 27,000건, 512K에서 런 100~101개 | 같음 |

이 차이로 테스트의 4, 5번 검사가 다른 병합 경로를 탔다. OOS 브랜치에서는 pad를 `varchar(2048)` 로 줄여 행이 inline target 안에 머물게 고쳤다(cubrid-testcases-private-ex `feature/oos-merge` `565a958b6`). 이 이슈의 수락 조건에 있는 `cbrd_27236_merge` 수치 갱신은 develop의 TC를 바꾸므로, 다음 develop → OOS TC 병합에서 이 변경과 겹칠 수 있다(추정).

### 함께 정할 사항

- 섹터 합에 해당 heap의 OOS 파일 섹터도 더할지 정한다. 측정 2의 원래 데이터에 더하면 워커당 (61 + 71) / 8 = 16으로 develop과 같아진다고 추정하지만, 구현해 재지는 않았다.
- 인덱스 컬럼이 아닌 값만 OOS에 있는 테이블에서는 OOS 섹터를 더하면 정렬 데이터보다 큰 값이 기준이 된다. 이 과대 추정이 임시 공간에 문제가 되는지 확인한다.
- 병렬 분할은 heap 섹터를 워커에게 나누는 구조라서, 측정 1처럼 heap이 2섹터면 기준 값을 바꿔도 워커 8개에 일을 나눌 수 없다. 이 이슈에서 팬인만 다룰지, 병렬 분할까지 다룰지 정한다.
