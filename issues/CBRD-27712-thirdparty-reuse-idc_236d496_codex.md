# [CBRD-27712] 3rdparty 재빌드 없는 재사용으로 CI 시간 및 네트워크 사용 절감

## Issue Triage

**이슈 수행 목적**: 한 번 빌드한 3rdparty를 재빌드 없이 계속 재사용할 수 있도록 하여, GHA build CI 수행 시간과 사내 IDC의 외부 네트워크 사용을 줄인다. **개발자의 기존 빌드 경험에는 영향이 없어야 한다.**

**이슈 수행 이유**: 재사용 방법은 약 2년 전에 구상했으나 당시에는 필요성이 크지 않아 진행하지 않았다. 최근 사내 IDC 인터넷 속도가 제한되면서, QA팀 강태우님으로부터 수주간 지속적으로 개선 요청을 받았다. 제한된 네트워크 환경에서 반복 다운로드와 재빌드 비용을 줄일 필요가 커졌다.

**영향**: 다음 두 가지 효과를 기대한다. 실제 절감량은 ANALYSIS 단계에서 확인한다.

- **GHA build CI 시간 단축**: 이미 빌드한 3rdparty를 재사용하여 반복 빌드를 생략하고, 전체 CI 수행 시간을 크게 단축할 수 있다.
- **IDC 네트워크 부담 완화**: 재사용 가능한 3rdparty를 다시 준비하기 위해 외부 다운로드를 강제로 수행할 필요를 없애고, 다른 업무가 사용할 수 있는 가용 대역폭을 확보할 수 있다.

**이슈 수행 방안**: 기존 이슈의 3rdparty 분리 빌드 및 경로 지정 재사용 방향을 유지한다. 개발자의 기존 빌드 명령과 절차를 유지하면서 적용하며, 상세 구현과 CI 적용 방식은 TBD - ANALYSIS 단계에서 결정한다.

## Description

### 무엇이 문제인가

CUBRID 빌드에 필요한 3rdparty가 변경되지 않았더라도, 새 빌드 환경이나 준비 상태를 초기화한 환경에서는 이를 다시 준비해야 할 수 있다. 반복 빌드로 시간이 소요되고, 필요한 파일이 보존되어 있지 않으면 외부 다운로드도 필요해진다.

한 번 빌드한 산출물을 보관하고 호환되는 후속 빌드에서 계속 재사용할 수 있어야 한다. 이때 개발자의 기존 빌드 명령과 절차를 유지해야 한다.

### 왜 문제인가

CI에서는 CUBRID 변경의 빌드·검증 결과를 확인해야 한다. 변경되지 않은 3rdparty의 반복 빌드는 이 결과를 받기까지의 대기를 늘린다. 산출물을 재사용하면 이 단계를 생략할 수 있어 GHA build CI 수행 시간을 크게 단축할 수 있을 것으로 기대한다.

사내 IDC에서는 최근 인터넷 속도 제한으로 외부 네트워크 사용을 줄일 필요가 커졌다. 반복 다운로드는 제한된 대역폭을 사용하고 빌드 대기도 늘린다. 이를 피하면 다른 업무에 사용할 수 있는 가용 대역폭 확보를 기대할 수 있다. 산출물 공급에 필요한 전송까지 포함한 실제 절감량은 ANALYSIS에서 확인한다.

### 왜 해결해야 하는가

작성자는 약 2년 전에도 재사용 방법을 구상했으나, 당시에는 필요성을 크게 느끼지 않아 진행하지 않았다. 최근 IDC 인터넷 속도가 제한되면서 QA팀 강태우님이 수주간 지속적으로 개선을 요청하여 착수 필요성이 커졌다.

개선을 미루면 재사용할 수 있는 3rdparty를 다시 준비하는 시간과 네트워크 사용이 누적된다. 개발자의 기존 빌드 경험을 유지하면서 재사용 기능을 제공하여, CI 대기 시간과 IDC 외부 네트워크 사용을 함께 줄일 필요가 있다.

## Triage Request

QA팀의 지속적인 요청과 IDC 네트워크 제약을 배경으로, 3rdparty 재사용을 통한 빌드·네트워크 비용 개선 과제로 확인하고 작성자에게 ANALYSIS를 배정할 것을 요청한다. 분석에서는 재사용 조건, 개발자 빌드 경험 유지 방안, GHA build CI 적용 방식과 IDC 외부 다운로드 감소 효과를 확인한다.

## Specification Changes

- 한 번 빌드한 3rdparty 산출물을 CUBRID와 분리하여 보관하고, 호환되는 후속 빌드에서 경로를 지정해 재빌드 없이 재사용할 수 있어야 한다.
- 재사용 가능한 산출물이 준비되어 있으면, 해당 의존성을 다시 준비하기 위한 외부 다운로드를 강제하지 않아야 한다.
- 개발자의 기존 빌드 명령과 절차를 유지하며, 재사용 기능 때문에 추가 수동 작업을 요구하지 않아야 한다.
- 의존성이나 빌드 환경이 달라져 재사용할 수 없는 산출물을 잘못 사용하지 않아야 한다.

## Acceptance Criteria

- [ ] 호환되는 후속 CUBRID 빌드에서 이미 빌드한 3rdparty를 재빌드 없이 계속 재사용할 수 있다.
- [ ] 재사용 가능한 산출물이 준비된 조건에서 해당 의존성의 외부 다운로드를 반복하지 않는다.
- [ ] 개발자가 기존 빌드 명령과 절차로 빌드·설치를 완료하며, 추가 수동 준비 작업이 필요하지 않다.
- [ ] 대표 GHA build CI 조건에서 재사용 전후의 수행 시간을 비교하고, IDC 적용 조건에서 외부 네트워크 사용 변화를 확인한다. 비교 조건과 최종 목표 수치는 ANALYSIS에서 정한다.
- [ ] 재사용 조건에 맞지 않는 산출물을 잘못 사용하지 않으며, 기존 빌드·설치 결과에 회귀가 없다.
